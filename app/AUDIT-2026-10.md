# October 2026 hardening

Version 1.2.3 keeps the existing UI, hosted model routing and own-model workflow.

- Saving an API key now requires OS-backed encryption. Linux `basic_text` storage is refused. Existing plaintext keys are migrated when a secure keychain is available; if it is unavailable, the old setting is retained for recovery and is not silently used.
- Privileged IPC handlers accept only the app's owned top-level renderers. General settings updates cannot replace account credentials, an API key or the device identifier.
- A settings file containing only malformed prompts recovers to a valid default prompt.
- Settings writes use restrictive permissions on POSIX systems.
- Compatible patches for `http-cache-semantics` and `source-map-js` were installed. Other development-tool advisories need upstream fixes or a separately tested toolchain migration.

The relay now cancels upstream work when the client disconnects, respects response backpressure, bounds stale authorization during an account-service outage, and limits simultaneous cloud transcription connections and buffered audio. Hosted plan sizes and model routing are preserved.

Validation includes desktop unit tests, TypeScript checks, an isolated Electron own-key smoke test, relay unit tests, and a local HTTP integration test for streaming and cancellation. No real microphone, customer conversation or provider request is used by those fixtures. macOS/Linux packages require their platform build jobs; successful packaging is separate from physical-device testing.
